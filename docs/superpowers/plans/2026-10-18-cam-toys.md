# cam-toys Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Five standalone browser camera toys (ASCII, motion, shader, hands, pose) plus an index page, readable enough to learn from.

**Architecture:** Vanilla ES modules, no build. `cam.js` is the only shared code. Each toy is one `.html` with inline `<script type="module">`, a `how it works` comment block on top, and a mirrored `<canvas>` output.

**Tech Stack:** HTML/JS, Canvas 2D, WebGL1, `@mediapipe/tasks-vision@0.10.14` (jsDelivr, pinned, hands/pose only). Check current MediaPipe API with Context7 before Task 5.

**Spec:** `docs/superpowers/specs/2026-10-18-cam-toys-design.md`

## Global Constraints
- Vanilla HTML + JS. No framework, bundler, build step, or test framework.
- One self-contained file per toy, readable top to bottom.
- Camera needs `localhost` or HTTPS; ES modules need http (not `file://`). Run: `python -m http.server 8000`.
- Camera denied/missing: one plain message in the page. No retries or fallbacks.
- MediaPipe loaded from pinned CDN version in `hands.html` / `pose.html` only.
- Every toy starts with a `how it works` comment block and is linked from `index.html`.
- Out of scope: recording/export, settings UI, depth models, deployment.

## Review Focus
- Camera permission denied: message shown, no blank canvas or uncaught error.
- No camera device: same message.
- First frames before `video.videoWidth` is nonzero: draw loop must not throw or draw NaN.
- Hand/person absent from frame: no stale drawing, no exception.
- Portrait phone / window resize: canvas keeps video aspect ratio, no stretch.
- Display is mirrored (selfie view); MediaPipe x-coords must be mirrored to match.

### Task 1: Shared helper, index, README

**Files:**
- Create: `cam.js`, `index.html`, `README.md`

**Interfaces:**
- Produces: `cam.js` exports
  - `startCamera(): Promise<HTMLVideoElement>`: `getUserMedia({video:{facingMode:'user'}})`, attaches to a hidden `<video playsinline muted>`, resolves once playing with `videoWidth > 0`; rejects on failure.
  - `showError(msg: string): void`: replaces `document.body` content with a single `<p>` containing `msg`.
  - `fitCanvas(canvas: HTMLCanvasElement, video: HTMLVideoElement): void`: sets canvas pixel size to video size (no stretch).

- [ ] **Step 1:** Write `cam.js` per interfaces. `startCamera` error text: `"Camera unavailable: " + err.name`.
- [ ] **Step 2:** Write `index.html`: title, list of 5 links (`ascii.html`, `motion.html`, `shader.html`, `hands.html`, `pose.html`) with one line each. Write `README.md`: what it is, run command, "camera needs localhost/HTTPS".
- [ ] **Step 3:** Run `python -m http.server 8000`, open `http://localhost:8000`. Expected: index renders, no console errors; links 404 until later tasks (fine).
- [ ] **Step 4:** Commit: `git add -A && git commit -m "feat: cam helper, index, readme"`

### Task 3: Motion toy

**Files:**
- Create: `motion.html`

**Interfaces:**
- Consumes: `startCamera`, `showError`, `fitCanvas`.

- [ ] **Step 1:** Implement frame differencing on a downscaled (~160 px wide) buffer: keep previous grayscale `Uint8Array`; per pixel `abs(cur-prev) > THRESH` (const `THRESH = 30`) marks motion. Display canvas shows mirrored video with a decaying trail layer (fade previous trail each frame, paint motion pixels bright). Skip diff on the first frame (no previous). Key `t` toggles trails/heatmap mode. Comment block explains differencing, threshold, decay.
- [ ] **Step 2:** Add wave-to-pop bubbles: spawn ~10 circles at random positions; a bubble pops when motion pixel count inside its radius exceeds 15% of its area; respawn after 1 s.
- [ ] **Step 3:** Verify: wave a hand over a bubble, expected it pops and respawns; sit still, expected no motion pixels and no pops. Resize window: no stretch.
- [ ] **Step 4:** Commit: `git add motion.html && git commit -m "feat: motion trails and bubbles"`

### Task 4: WebGL shader toy

**Files:**
- Create: `shader.html`

**Interfaces:**
- Consumes: `startCamera`, `showError`, `fitCanvas`.

- [ ] **Step 1:** Implement fullscreen-quad WebGL1 setup, upload `<video>` to a texture each frame (`texImage2D`, `CLAMP_TO_EDGE`, `LINEAR`, no mips), uniforms `uTex`, `uTime`, `uMode`. Fragment shader modes: 0 passthrough mirrored, 1 RGB split glitch (offset channels by `sin(uTime)`-driven amount plus horizontal row jitter), 2 kaleidoscope (polar fold, 6 segments). Keys `1` `2` `3` switch mode. Show a shader-compile error via `showError` with the info log. Comment block explains texture upload, UVs, and polar coords.
- [ ] **Step 2:** Verify: all three modes visibly differ and animate; mode 0 matches a mirrored webcam view.
- [ ] **Step 3:** Commit: `git add shader.html && git commit -m "feat: webgl shader effects"`

### Task 5: Hands toy (MediaPipe)

**Files:**
- Create: `hands.html`

**Interfaces:**

- [ ] **Step 1:** Load `HandLandmarker` from `https://cdn.jsdelivr.net/npm/@mediapipe/tasks-vision@0.10.14` with wasm base `.../wasm` and model `https://storage.googleapis.com/mediapipe-models/hand_landmarker/hand_landmarker/float16/1/hand_landmarker.task`, `runningMode: "VIDEO"`, `numHands: 2`. - [ ] **Step 3:** Verify: finger draws lines on screen; pinch stops drawing; removing the hand causes no console errors; `c` clears.
- [ ] **Step 4:** Commit: `git add hands.html && git commit -m "feat: hand tracking air-draw"`
